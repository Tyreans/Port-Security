Módulo 4 · Criterio TecNM (SCD-1004)

Buenas prácticas complementarias de seguridad en conmutación

Port Security controla quién se conecta físicamente, pero no inspecciona tramas DTP, ofertas DHCP ni paquetes ARP. Así se construye una defensa en profundidad real en Capa 2.

1. Defensa en profundidad en la Capa de Enlace

Un error frecuente consiste en asumir que activar Port Security resuelve todos los riesgos de la red local. En arquitectura empresarial, la seguridad nunca depende de un único control.

Aunque Port Security limita la identidad física (MAC) y el número de terminales por puerto, coexiste con vectores independientes como la negociación maliciosa de enlaces troncales (VLAN Hopping), servidores DHCP falsos (DHCP Spoofing) o el envenenamiento de tablas ARP (ARP Poisoning).

Directivas de Switch Hardening

  • Apagar y aislar en una VLAN Blackhole todos los puertos sin uso.
  • Forzar modo acceso y desactivar DTP (switchport nonegotiate).
  • Filtrar servidores DHCP con DHCP Snooping.
  • Validar respuestas ARP con Dynamic ARP Inspection (DAI).
  • Bloquear suplantaciones IP con IP Source Guard (IPSG).

2. Aislamiento de interfaces no utilizadas (Blackhole VLAN)

Por defecto, todos los puertos de un switch vienen encendidos (no shutdown) y asignados a la VLAN 1, por donde circula tráfico de control (CDP, VTP, PAgP, STP). Cualquier toma RJ-45 vacía en una sala de juntas o pasillo da acceso inmediato a la red si no se endurece.

Mitigación en dos pasos

  1. Apagado administrativo (shutdown): coloca el puerto en Administratively Down sin señal eléctrica.
  2. Asignación a una VLAN de aislamiento (ej. VLAN 999): sin interfaz SVI (sin IP ni gateway) y sin enrutamiento. Si alguien reactiva el puerto por error, queda en un pozo sin salida.
Switch(config)# vlan 999
Switch(config-vlan)# name VLAN_Blackhole_Aislamiento
Switch(config-vlan)# exit
Switch(config)# interface range fastEthernet 0/11 - 24
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 999
Switch(config-if-range)# shutdown
Switch(config-if-range)# description PUERTO_NO_UTILIZADO_AISLADO

3. Supresión de DTP contra VLAN Hopping

Las interfaces Cisco operan por defecto en negociación dinámica de troncales (Dynamic Auto o Dynamic Desirable) mediante el protocolo propietario DTP (Dynamic Trunking Protocol).

El ataque (Switch Spoofing): un atacante con herramientas como Yersinia o Scapy inyecta tramas DTP pidiendo formar un enlace troncal 802.1Q. Si el puerto acepta, el intruso obtiene acceso directo al tráfico de todas las VLANs del switch.

Regla de oro de hardening

  • switchport mode access: fuerza el puerto a operar exclusivamente como acceso.
  • switchport nonegotiate: suprime por completo el envío y recepción de tramas DTP.
Switch(config)# interface gigabitEthernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport nonegotiate
Switch(config-if)# switchport access vlan 10

4. Port Security frente a tecnologías complementarias

Port Security valida únicamente la cabecera Ethernet (MAC de origen). Si un equipo con MAC legítima y autorizada envía ofertas DHCP falsas o respuestas ARP envenenadas, Port Security no lo detecta: se requieren las siguientes capas.

Capa 2 pura · Identidad física

4.1 Port Security

Qué analiza: dirección MAC de origen en la trama Ethernet.

Qué mitiga: conexión de dispositivos físicos no autorizados (Rogue Devices) y agotamiento de la tabla CAM (MAC Flooding).

Limitación: es ciego al contenido IP, DHCP o ARP de las tramas que provienen de una MAC ya permitida.

Pilar base · Binding Database

4.2 DHCP Snooping

Qué mitiga: servidores DHCP clandestinos (Rogue DHCP) y agotamiento de IPs (DHCP Starvation).

Cómo opera: divide los puertos en Trusted (hacia el servidor legítimo) y Untrusted (usuarios). Descarta cualquier paquete DHCP Offer o DHCP ACK que entre por un puerto no confiable y construye la Binding Table (MAC | IP | Lease | VLAN | Puerto).

Anti-MitM · Validación ARP

4.3 Dynamic ARP Inspection (DAI)

Qué mitiga: envenenamiento de tablas ARP (ARP Spoofing / Poisoning), base de los ataques Man-in-the-Middle en LAN.

Cómo opera: intercepta cada paquete ARP en puertos Untrusted y verifica que el par {IP, MAC} coincida con la Binding Table generada por DHCP Snooping. Si no coincide, descarta el paquete.

Filtro en hardware · Anti-IP Spoofing

4.4 IP Source Guard (IPSG)

Qué mitiga: suplantación de direcciones IP (IP Spoofing) desde un puerto de usuario.

Cómo opera: utiliza la base de datos de DHCP Snooping para instalar una ACL dinámica en el hardware del puerto: solo deja pasar paquetes IP cuyo origen coincida exactamente con la IP asignada a esa MAC.

6. Plantilla maestra de endurecimiento de un puerto de acceso

Configuración integral para una estación de trabajo empresarial con teléfono IP y PC, cumpliendo estándares de la industria y criterios de evaluación académica:

  • Bloque 1: fija el modo acceso y apaga DTP contra VLAN Hopping.
  • Bloque 2: activa Port Security para 2 dispositivos (voz + datos), aprende las MAC en modo sticky y audita infracciones con restrict.
  • Bloque 3: acelera la convergencia con portfast y protege el árbol STP con bpduguard.
Switch# configure terminal
Switch(config)# interface gigabitEthernet 0/5
Switch(config-if)# description CONEXION_USUARIO_ESTACION_05

! 1. Fijación en modo acceso y supresión de DTP
Switch(config-if)# switchport mode access
Switch(config-if)# switchport nonegotiate
Switch(config-if)# switchport access vlan 10

! 2. Implementación de Port Security
Switch(config-if)# switchport port-security
Switch(config-if)# switchport port-security maximum 2
Switch(config-if)# switchport port-security mac-address sticky
Switch(config-if)# switchport port-security violation restrict

! 3. Medidas complementarias de optimización y seguridad
Switch(config-if)# spanning-tree portfast
Switch(config-if)# spanning-tree bpduguard enable
Switch(config-if)# exit

7. Preguntas de reflexión para el cierre de la exposición

¿Por qué combinar shutdown y una VLAN Blackhole en vez de solo apagar el puerto?

«Si un puerto ya está en shutdown, ¿qué aporta moverlo además a una VLAN 999 sin salida?»

Respuesta sugerida: protege contra errores administrativos o scripts que ejecuten no shutdown por accidente. Si el puerto se reactiva, el intruso queda aislado en una VLAN sin SVI, sin DHCP, sin gateway y fuera de la VLAN 1.

¿Puede un usuario legítimo hacer ARP Poisoning en un puerto con Port Security activo?

«Un puerto tiene switchport port-security con maximum 1 y modo restrict. ¿Puede esa misma PC ejecutar un ataque de envenenamiento ARP?»

Respuesta sugerida: sí. Como la trama sale con la dirección MAC legítima ya autorizada en el puerto, Port Security la da por válida. La falsificación va dentro del payload ARP, por lo que se necesita Dynamic ARP Inspection (DAI) para bloquearla.

¿Qué función cumple switchport nonegotiate si ya se configuró switchport mode access?

«Si el puerto ya fue declarado de acceso estático, ¿por qué añadir switchport nonegotiate?»

Respuesta sugerida: garantiza que la interfaz deje de emitir tramas DTP por completo, evitando divulgar información de negociación y cerrando cualquier vector de consulta o manipulación de trunking.

Cierre del recorrido

Combinar Port Security con el aislamiento de puertos inactivos, la supresión de DTP y la tríada DHCP Snooping + DAI + IPSG transforma una capa de enlace confiada por defecto en una frontera verificable puerto por puerto.
